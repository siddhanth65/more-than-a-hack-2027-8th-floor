# FIX_NOTES - PathCRF on the real tactical feed (2026-11-11), for the owner of calibration (worktree possession-kh)

## What was wrong
PathCRF was near chance in the real second half (accuracy 0.58 against the confident-control pseudo-labels, 0.47 against the tag-implied team; first half 0.90 / 0.71),
while it is 0.97 / 0.95 on sim H1 / H2. It is NOT an orientation or team-label problem (tested):
- Direction: both rules (mean-x per team; keeper = most extreme median-x slot) say home attacks +x in H1 and -x in H2 (away the reverse); the pipeline's own `direction_of_play` agrees (home +1 / -1), and agrees with the mean-x rule on 12/12 sim halves. The wrapper (`run_infer.py`) already derives left/right from the data per half. Feeding H2 with x mirrored, x+y mirrored, y mirrored, teams swapped or combinations: 0.49-0.58 (PathCRF is invariant to team swap by construction). Mirroring H1 leaves 0.90.
- Team labels: slot-to-team coherence is the same in both halves (0.604 vs 0.601); slot column order equals the Player order of the xml; visible players per team about 10 in both halves (10.0-10.5); per-chunk goalkeeper pick plausible in both; no mid-half side flip (0 % of chunks flipped).
- The failure is chunk-wise (30 of 78 H2 chunks inverted, 4 of 79 in H1), scattered through the half.
What fixes it: smoothing the player positions in time before PathCRF. Centred moving average, window 0.2 s: no effect (H2 0.573); 0.44 s: 0.948; 1 s: 0.956; 2 s: 0.961; H1 unchanged (0.897 -> 0.899-0.903). Removing >15 m/s jump frames, de-duplicating repeated frames: no effect. Using only the 11 most-present slots per team: 0.866.
The real tracks are far smoother than the simulator (median |2nd difference| 0.0014 m vs 0.055 m) and have kinks in 0.8-1 % of player-frames; PathCRF's velocity/acceleration features are evidently fragile on that structure in some stretches of H2 (root cause beyond "needs >= 0.4 s smoothing" not established). On sim halves smoothing changes nothing (6 halves: 0.958-1.0 vs 0.916-0.989 before, never worse).

## The fix (branch exp-arb)
- `mtah/evidence/pathcrf.py` (commit 0dea458): `PathCRFParams.smooth_s` (default 0 = off, so every registered cache/candidate is unchanged), `smooth_positions()` (NaN-aware centred moving average, visible frames only), `write_half_input(..., smooth_s)`; the cache stores `smooth_s` and a lookup with another value is a miss (old caches count as 0). `mtah/pipeline.py`: `smooth_s` read/written in the config only when non-zero.
- `scripts/make_candidate.py` (0796a64): `--pathcrf-smooth 1.0` (uses its own cache `runs/cache/pathcrf_fx`, never overwrites the registered one).
- `scripts/arb_run.py`: env `ARB_PCRF_CACHE` / `ARB_PCRF_SMOOTH` for the masked-ball runs.
- Tests: `tests/test_pathcrf_smooth.py` (smoothing keeps NaN and ramps, off = identity, cache key includes smooth_s).
- Rule: smooth_s = 1.0 s for the real tactical feed; 0 for the simulator (it is already noisy and unaffected). NOT a per-half or per-match special case: one parameter per feed. If SkillCorner / Metrica halves are fed to PathCRF, check them with `scripts/arb_pcrf_variants.py` (asis vs smooth) before trusting them.
